# 恢复与排查

## 已有适配可用时

不需要因为关闭电脑而重新提权、安装模块或软重启。仓库整理不要求立即在正在使用的平板上更新 APK。

## 双栏还在、输入法又自动弹出

先检查 Vector 是否激活、模块是否启用，以及作用域是否含目标应用。0.6.0-alpha 起还需要框架支持 libxposed API 102；低版本框架无法加载新版模块。原生规则与输入法注入是两条独立路径；完整重启后保留双栏但失去键盘拦截并不矛盾。

从旧 API 版本升级后，要结束并重新打开目标应用；新版没有启用自动热重载，也不提供旧 API 降级路径。

## 关闭输入法与启动补充功能

在 LSP / Vector 中取消目标应用的模块作用域，结束并重新打开目标应用即可。原生双栏配置仍然保留。不要为关闭此模块而删除其他模块或应用数据。

## 恢复原生规则

使用这台设备修改前保存的备份：

```sh
python tools/native_rules.py restore --backup backups/bili-before.json
python tools/native_rules.py restore --backup backups/coolapk-before.json
```

备份必须来自相应设备、相应系统版本；不要交换完整配置备份。工具只能检查当前规则是否符合备份前后状态，无法证明备份的设备来源。若规则已被外部改变，先检查差异，不强制覆盖。

原生规则恢复与 LSP 作用域是独立操作。要完全撤销本项目效果，两者都应处理。平行视窗系统开关和拖动比例需要在系统界面按需调整。

## 安装等待或卡顿

出现长时间安装不返回、ADB 无响应或界面卡顿时，停止追加安装和重启命令。中止电脑端安装客户端并不保证设备端安装事务已经取消；恢复后必须重新核对实际安装版本。

若设备完全失去响应、无法软件恢复，iQOO 设备通常可同时长按电源和音量减约 10–15 秒强制重启，以设备说明为准。完整重启会失去临时 root；先确认系统流畅，再逐项恢复环境。

## 软重启

本项目不提供软重启按钮，也不把软重启作为构建、安装或规则应用的自动步骤。实验设备此前使用 KernelSU `ksud soft-reboot` 保留过临时 root，但还观察到旧 Vector 服务残留与新服务冲突。该流程尚未整理为可普遍推荐的一键恢复方案。

已知卡死原因尚未确定时，不应反复执行提权与软重启脚本。恢复稳定性优先于继续适配。
